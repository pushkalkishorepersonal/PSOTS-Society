## Platform Principles

```
1. Never replace Telegram — complement it
2. Telegram = real-time chat, Platform = permanent knowledge
3. Self-sustaining by Month 8 (October 2026)
4. Charge only what it costs — no profit, no markup
5. Admin team of 5-10 people — not dependent on one person
6. Every feature must work without admin for 2 weeks
7. Privacy first — no personal data exposed without consent
8. EC-backed content only for rules/guidelines
```

## Background Services — Google Cloud / GitHub Actions (Free Tier)

### Philosophy
Start with GitHub Actions (simplest).
Migrate to Google Cloud Run when complexity grows.
Both free. Same Python scripts. Zero rework.

### Phase 2 — Start Here
EC Broadcast Sync (GitHub Actions):
  Schedule: Every 6 hours
  Manual: Admin panel "Sync EC" button
  Output: Pending EC messages → admin reviews → publishes
  Cost: ₹0

### Phase 3 — When Food Dashboard Launches
Food Menu Extractor (Cloud Run):
  Schedule: Every morning 8 AM
  Process: Foodies Telegram → extract menus →
           update seller profiles on platform
  Value: Sellers post on Telegram as usual
         Platform auto-syncs — zero extra work for them
         Removes biggest adoption barrier
  Cost: ₹0

### Phase 4 — When User Base Grows
Group Health Monitor — daily digest in admin panel
Wiki Article Generator — EC messages → draft articles
Contact Card Extractor — Hire Services → contact cards
Monthly Community Report — auto email to superadmin
All cost: ₹0

### Service Architecture (When Ready)
One Cloud Run service — multiple endpoints:
  POST /sync-ec        → EC broadcast sync
  POST /sync-menus     → Daily food menu sync
  POST /extract-wiki   → Wiki article generation
  POST /health-check   → Group activity monitor
  POST /sync-contacts  → Contact card extraction

Total Cost: ₹0
Enables: Platform runs itself with minimal admin effort
